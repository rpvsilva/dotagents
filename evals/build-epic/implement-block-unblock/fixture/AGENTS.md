# todo sandbox

A tiny todo CLI used to test the `build-epic` skill. Checks: `python -I -m pytest -q -c pyproject.toml`. Commits: Conventional Commits. Agents may merge PRs here once CI is green and a fresh-context reviewer has read the whole diff, with `gh pr merge --squash --match-head-commit <sha>`, where `<sha>` is the head commit CI passed on (so a commit pushed after the green check is never merged untested), except a PR that touches `.agents/`, `.github/`, `tests/`, `AGENTS.md`, `pyproject.toml`, `requirements-ci.txt`, any `conftest.py`, any `.py` file in the repo root, adds a top-level directory, adds `pytest.ini`, `.pytest.ini`, `pytest.toml`, `.pytest.toml`, `tox.ini` or `setup.cfg`, or adds a `.pyc`, `.pyd` or `.so` file anywhere (`__pycache__/` included; `.gitignore` does not stop `git add -f`): CI runs that PR's own workflow, tests and pytest setup, so it could make itself pass, Python imports a compiled file in place of the reviewed source, and `.agents/` holds the risks only Rui may accept; leave it for Rui to approve and merge. Package code runs inside pytest too, so green CI alone proves nothing: also leave for Rui any PR whose code ends the process, replaces it, or changes how pytest or the interpreter runs, by any means; for example `os._exit`, `sys.exit`, `atexit`, `os.exec*`, `os.kill`, signals, patching `sys.modules`, or imports of `pytest`, `_pytest` or `pluggy` outside `tests/`.
Locally, run checks with `.venv/bin/python -I -m pytest -q -c pyproject.toml` (create it with `python3 -m venv .venv && .venv/bin/pip install --require-hashes -r requirements-ci.txt`), and only on code Rui or a fresh-context reviewer has read, or in a sandbox without the App token script (see Identity): the checks run that code, and it could mint a merge-capable token.

Run the CLI with `python -m todo <command>` (`python -m todo.cli` works too). Items live in `$TODO_FILE` (default `~/.todo.json`). User-facing usage, the sync rule and known limits are in `README.md`; keep it current when a command or flag changes.

## Packages

- `todo/storage/`: the `Item` model (with a UTC `updated_at` stamp, `tags`, `priority` and the recurrence rule `every`) and the date, tag, priority and recurrence rules (`model.py`), the `Store` interface (`base.py`), the JSON backend `JsonStore` (`json_store.py`).
- `todo/cli/`: argparse wiring (`app.py`), one module per command in `commands/`, terminal output in `format.py`. Commands: `todo add TITLE [--due DATE] [--tag TAG[,TAG...]]... [--priority high|medium|low] [--every RULE]`, `todo list [--overdue] [--tag TAG]... [--priority P] [--open|--done] [--search TEXT] [--sort priority|due]`, `todo search TEXT`, `todo done ID`, `todo skip ID`, `todo stop ID`, `todo tag ID [+TAG[,TAG...]|-TAG[,TAG...]]...`, `todo priority ID high|medium|low|none`, `todo remind`.
- `todo/export/`: render items as CSV (`csv_export.py`) or Markdown (`markdown.py`); `FORMATS` maps `--format` names to renderers. Command: `todo export --format csv|md [--out FILE]` plus the `todo list` filters (`--tag`, `--priority`, `--open|--done`, `--search`, `--sort`), selected by `todo/cli/select.py`.
- `todo/sync/`: last-write-wins merge by item `id` and `updated_at` (`merge.py`; the whole item wins, tags and priority included), then one item per recurring occurrence, by the hidden `series_id` and `occurrence` on `Item`, and a series stopped on either side stays stopped, the remote store from `$TODO_REMOTE`, a JSON file path (`remote.py`), pull-then-push (`sync.py`). Command: `todo sync`.

Tests mirror the packages: `tests/<package>/<name>_test.py`. Shared fixtures (`cli`) are in `tests/conftest.py`.

## Identity
Agents act on GitHub as the `rpvsilva-agent` App, never as Rui: prefix every `gh` call with `GH_TOKEN="$(~/Desktop/Projects/dotagents/scripts/gh-app-token.sh rpvsilva/build-epic-sandbox)"` (issues, labels, comments, PRs, merges). If the script or its App key is missing, stop and ask.
