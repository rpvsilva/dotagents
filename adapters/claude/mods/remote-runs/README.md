# remote-runs

A Claude Code mod: `/remote-runs` opens a pane listing the remote-agent runs of the session's repo. It only reads: each run is a folder `remote-agent/<run>/` in the repo's common git dir (`git rev-parse --path-format=absolute --git-common-dir`) or in a linked worktree's git dir under it (`worktrees/<name>/`). With no runs, outside a git repo, or where Claude Code runs no processes (the desktop app, VS Code), the pane says `no remote runs in this repo`.

One row per run: its name (else the run id), state, elapsed time, the claim / send / first-event timings and the last step (the last line of `progress.log`), all from `run.json` and `progress.log`. States are those `run.json` holds (`starting`, `running`, `done`, `failed`), plus `stopped` when it says starting or running but its pid is gone or belongs to a later process (`ps -o pid=,lstart=` in the C locale, as `remote-agent` wrote it; a `kill -9` or a reboot; a run called stopped has its `run.json` read again first, so one that ended between the read and `ps` shows how it ended), and `unknown` for a folder with no `run.json`. Rows: every starting, running or stopped run, then the newest finished, 20 in all, newest first; the first nine have hotkeys `1`-`9`.

Pressing a row (a click, Tab then Enter, or its hotkey) shows that run's log in place of the list, read from its `transcript.jsonl`: the agent's text, each tool call as `-> <tool> <summary>` (the summary the sandbox prints: the input's `command`, `file_path`, `pattern`, `description`, `url` or `path`), each result as `<- <tool>: <first line>` or `<- ERROR <tool>: <first line>`, then `done in <s>s, $<cost>` or `FAILED <subtype>`, in order; `session started (<model>)` for the init event; thinking and other system events are left out. A partial last line, a line that is not JSON and an event of an odd shape are skipped. Each line has its control characters and ANSI escapes stripped, secret-looking strings masked (`sk-ant-`, `ghp_` and the other `gh?_` tokens, `github_pat_`, Slack `xox?-`, AWS `AKIA`, JWTs, `Bearer`/`Basic` values, `user:password@` in URLs, a private key and all after it, and the value of any name holding `KEY`, `TOKEN`, `SECRET` or `PASSWORD`), then is cut to one row of 160 characters. The masking is best effort: `remote-agent` already redacts the Claude token at the source, and this catches other tokens of the shapes listed, not every secret. An empty, missing or unreadable transcript says `waiting for the first event`. `Back` (hotkey `b`) returns to the list. The log's header shows the transcript's path beside `Copy path` (hotkey `c`), which copies it to the clipboard of the surface that pressed and toasts `copied`, or `not copied` and why (a surface with no clipboard, no clipboard tool); the path stays drawn as text either way. A finished run's log (done, failed or stopped) ends with `to resume: remote-agent resume <run> <worktree>` (the worktree from `run.json`, shell-quoted) and the warning that it places a session the sandbox wrote, which may hold forged turns, so read `session.jsonl` first; a run with no `session.jsonl` says it cannot be resumed. The pane never places the session itself.

A timer reads the folders every 1.5 s, from session start, so the pane is current without a command; it rereads `run.json` and `progress.log` only when their size or mtime changed, never rereads a done or failed run, runs one `ps` per tick for the live runs, and redraws only when a row would show something new. Elapsed time is shown to the minute while a run goes on, so a running run does not redraw every tick.

The same timer, pane open or not, keeps a status line (`remote: 2 running, 1 failed`; a zero part left out, cleared when both are zero; starting runs count as running, and failed or stopped runs count for 60 minutes after they ended) and raises one native notification per run that ends, titled `remote run`: `<name> done`, `<name> failed (exit <code>)` or `<name> stopped`. The status line is set only when its text changes. The notified run folders are kept in the mod's store, per repo (`notified:<common git dir>`; past 1,000, the oldest folders no longer on disk are dropped, never one still there), so a reload or a new Claude Code process does not notify again; the first tick of a process marks every run already finished without notifying, and a notification no channel sent (notifications turned off) is marked too, not retried.

`./install.sh claude` links this folder to `~/.claude/skills/remote-runs`, where Claude Code loads it as a plugin and watches it: saving a file here reloads it in a running session.

## Files

- `hooks/main.tsx`: the hooks module. Registers `/remote-runs`, starts the timer, opens the pane, reads the run folders, draws the list or a run's log, sets the status line and notifies. Every `$.fs` and `$.process` call is caught and means "no data", so a missing folder or a failing `git` never prints a failed-hook line.
- `hooks/runs.ts`: plain logic (parsing a run folder, liveness, which rows, their words, the status line and notification texts) with no `claude-code` import at run time, tested by `hooks/runs.unit.ts` under `node --test`. Text from a run folder (the name, the worktree, the last step) goes through `printable`, which drops control characters, so an escape sequence a sandbox wrote never reaches the terminal.
- `hooks/transcript.ts`: plain logic for the log (`parseLines`, `renderEvent`, `mask`, `oneLine`, `resumeHint`, `copiedText`), tested by `hooks/transcript.unit.ts` under `node --test`.
- `hooks/state.d.ts`: the state contract (`plugin.json` `types`). Change an atom's `shape` tag when its fields change.
- `hooks/main.test.tsx`: engine tests under `claude plugin test`, with the engine's answers faked.
