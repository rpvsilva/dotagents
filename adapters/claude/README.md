# Claude Code adapter

- `agents/*.md`: subagent definitions, linked into `~/.claude/agents/` by `install.sh`. Each one only points at a brief in `~/.agents/skills/`.
- `hooks/*.json`: hook config snippets. Each one calls a script in `~/.agents/hooks/` (linked to `scripts/hooks/` by `install.sh`). `guard-merge.json` (also in the Codex and Cursor adapters) blocks `gh pr merge`, PR approvals and pushes to main in repos with a `.review-gate.yml`. `guard-secrets.json` (also in both) blocks file tools and shell commands on secret files (`.env*`, `*.pem`, keys, `secrets/`) and commits adding a secret file or token, in every repo; Claude wires it on `Bash`, `Read`, `Edit`, `Write` and `Grep`, Codex on shell commands, Cursor on shell commands and file reads. `allow-task-cleanup.json` (Claude only) approves without asking a command that only deletes task branches (`task/<ticket>/<NN>`, `fix/security-<name>/<NN>`) or removes a worktree on one, so build-epic and security-audit don't stop to ask; ticket and fix branches still ask. Cursor needs no twin (its guard hooks already approve what they pass); Codex's hooks cannot approve. Shared hook code lives in `scripts/hooks/lib.sh`. `install.sh` merges them into `~/.claude/settings.json` with `scripts/merge-json.sh` (not linked, because that file also holds machine-local settings).
- `settings/agent-identity.json`: denies `gh pr review` and `gh auth token`, so Claude can't approve PRs or borrow Rui's GitHub login (see Pull requests in `AGENTS.md`). A guardrail against mistakes, not a security boundary. `install.sh` merges it into `~/.claude/settings.json`, like the hooks.
- `plugins.txt`: Claude Code plugins to install, one `<plugin>@<marketplace> <marketplace source>` per line. `install.sh claude` runs `scripts/claude-plugins.sh` on it, which adds missing marketplaces and installs missing plugins; a plugin already installed (even disabled) is left alone. Skipped when `claude` is not on PATH or `DOTAGENTS_SKIP_PLUGINS` is set.
- `mods/`: Claude Code mods (plugins of function hooks), one folder each holding `.claude-plugin/plugin.json`. `install.sh claude` links each into `~/.claude/skills/<mod>`, where Claude Code loads it as a plugin and watches it: saving a file reloads its hooks module in a running session, with no reinstall (a `claude -p` run always loads fresh). A mod's folder and `plugin.json` name match, and no skill may share it (`tests/repo.test.sh`). After moving the repo, run `./install.sh claude` again, as for every other link. Tests: `bash tests/mod.test.sh`. [`remote-runs`](mods/remote-runs/README.md) lists the repo's remote-agent runs (`/remote-runs`).
- MCP servers: `install.sh claude` adds `mcp/servers.json` at user scope with `claude mcp add-json`, and replaces a server whose config changed. Skipped like plugins.
- `telemetry/extract.py`: reads Claude Code session logs (`~/.claude/projects/`) into the neutral run JSON the `telemetry` skill reports on. Not linked; the skill reaches it through the repo. Tests: `python3 -m unittest test_extract` in that folder.
