# Claude Code adapter

- `agents/*.md`: subagent definitions, linked into `~/.claude/agents/` by `install.sh`. Each one only points at a brief in `~/.agents/skills/`.
- `hooks/*.json`: hook config snippets. Each one calls a script in `~/.agents/hooks/` (a folder of one link per file into `scripts/hooks/`, made by `install.sh`: the hooks library and each installed hook). `guard-merge.json` (also in the Codex and Cursor adapters) blocks `gh pr merge`, PR approvals and pushes to main in repos with a `.review-gate.yml`. `guard-secrets.json` (also in both) blocks file tools and shell commands on secret files (`.env*`, `*.pem`, keys, `secrets/`) and commits adding a secret file or token, in every repo; Claude wires it on `Bash`, `Read`, `Edit`, `Write` and `Grep`, Codex on shell commands, Cursor on shell commands and file reads. `allow-task-cleanup.json` (Claude only) approves without asking a command that only deletes task branches (`task/<ticket>/<NN>`, `fix/security-<name>/<NN>`) or removes a worktree on one, so build-epic and security-audit don't stop to ask; ticket and fix branches still ask. Cursor needs no twin (its guard hooks already approve what they pass); Codex's hooks cannot approve. `telemetry-save.json` (Claude only: other tools have no extractor) runs on `SessionEnd` and saves the whole session's run as `~/.agents/telemetry/<session id>.json` through `telemetry/extract.py --whole`, in the background so the session ends at once; it saves nothing, silently, when the `telemetry` Setting `auto_save` is false or anything fails. Shared hook code lives in `scripts/hooks/lib.sh`. `install.sh` merges them into `~/.claude/settings.json` with `scripts/merge-json.sh` (not linked, because that file also holds machine-local settings).
- `settings/agent-identity.json`: denies `gh pr review` and `gh auth token`, so Claude can't approve PRs or borrow the human's GitHub login (see Pull requests in `AGENTS.md`). A guardrail against mistakes, not a security boundary. `install.sh` merges it into `~/.claude/settings.json`, like the hooks.
- `plugins.txt`: Claude Code plugins to install, one `<plugin>@<marketplace> <marketplace source>` per line. `install.sh claude` runs `scripts/claude-plugins.sh` on it, which adds missing marketplaces and installs missing plugins; a plugin already installed is left alone, except one disabled with no `enabledPlugins` entry in `~/.claude/settings.json`, which it enables (one set to `false` there stays off). Skipped when `claude` is not on PATH or `DOTAGENTS_SKIP_PLUGINS` is set.
- `mods/`: Claude Code mods (plugins of function hooks), one folder each holding `.claude-plugin/plugin.json`. `install.sh claude` links each into `~/.claude/skills/<mod>`, where Claude Code loads it as a plugin and watches it: saving a file reloads its hooks module in a running session, with no reinstall (a `claude -p` run always loads fresh). A mod's folder and `plugin.json` name match, and no skill may share it (`tests/repo.test.sh`). After moving the repo, run `./install.sh claude` again, as for every other link. Tests: `bash tests/mod.test.sh`. [`agent-flow`](mods/agent-flow/README.md) draws the session's agents and the repo's remote-agent runs (`/agent-flow`).
- MCP servers: `install.sh claude` adds `mcp/servers.json` at user scope with `claude mcp add-json`, and replaces a server whose config changed. Skipped like plugins.
- `telemetry/extract.py`: reads Claude Code session logs (`~/.claude/projects/`) into the neutral run JSON the `telemetry` skill reports on, with `repo` and `date` (the UTC date of `start`). A line of the log that is not a JSON object, anywhere in it (half-written or cut at session end), is skipped, as is a subagent whose meta is unreadable, so the extractor never stops on a damaged log. `--whole` measures the whole session instead of the stretch since the last telemetry report, as the session-end save does. Not linked; the skill reaches it through the repo. Tests: `python3 -m unittest test_extract` in that folder.
